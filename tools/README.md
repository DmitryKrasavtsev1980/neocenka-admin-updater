# Dual-modem: 2× Huawei E3372-325 + 4 браузера

Фактическая раскладка (проверено 18.10.2026):

| | Модем A | Модем B | Кабель |
|---|---|---|---|
| Модель | E3372-325 | E3372-325 | — |
| SN | `W6S7S24A11001624` | `W6S7S24A11001577` | — |
| Оператор | MegaFon (25002) | beeline (25099) | — |
| Режим | **HiLink** (не stick!) | **HiLink** | — |
| LAN-адаптер | `192.168.8.103` | `192.168.8.107` | `192.168.1.94` |
| Публичный IP | `188.162.x.x` | `89.113.x.x` (меняется) | `45.94.23.94` |
| WAN (CGNAT) | `10.180.x.x` | `10.26.x.x` | — |
| Слот в коде | `A` | `B` | — |

Оба модема — **HiLink-прошивка**, веб-API на `192.168.8.1`. AT-хелпер
(`modem-at-helper`) для них **не нужен** — он для stick mode.

## Железо

```
[Baseus BS-HUB001, ВНЕШНЕЕ ПИТАНИЕ ОБЯЗАТЕЛЬНО]
   ├─ E3372-325 #1 (MegaFon)  → USB 2.0 порт хаба
   └─ E3372-325 #2 (beeline)  → USB 2.0 порт хаба
          │
          └── USB в ПК (Windows)
```

- Питание хаба включить **до** подключения стиков.
- Использовать только **USB 2.0** порты хаба. USB 3.0-порт (`Port_#0001.Hub_#0004`)
  глючит: `CM_PROB_FAILED_POST_START` / Code 43, модемы не поднимаются.
- Интернет у ПК — **по кабелю** (надёжнее). Модемы нужны только для парсинга.
- При первом подключении модем может быть режимом установщика (CD «HiLink», `D:\AutoRun.exe`).

## Сетевая проблема двух HiLink

У обоих модемов LAN `192.168.8.0/24`, шлюз `192.168.8.1`. В Windows три
default-маршрута, и запрос к `192.168.8.1` уходит «кто первый». Решение —
**не менять** LAN IP модема (API закрыт `100003`, перебор пароля рискован), а
прибивать исходящий трафик к адаптеру:

1. **хелпер смены IP** (`modem-hilink-helper`) — ходит в `192.168.8.1` с `localAddress`;
2. **прокси** (`modem-proxy`) — весь трафик Chrome уходит через свой модем.

## Старт всего

```powershell
powershell -ExecutionPolicy Bypass -File C:\Projects\ret\admin-updater\tools\start-dual-modem.ps1
```

Поднимет:

| Процесс | Порт | Кому |
|---|---|---|
| `modem-hilink-helper --slot A --iface 192.168.8.103` | 8891 | расширение модема A |
| `modem-hilink-helper --slot B --iface 192.168.8.107` | 8892 | расширение модема B |
| `modem-proxy --port 8881 --iface 192.168.8.103` | 8881 | Chrome на модеме A |
| `modem-proxy --port 8882 --iface 192.168.8.107` | 8882 | Chrome на модеме B |

Проверка: три ответа `api.ipify.org` через 8881 / 8882 / без прокси — **разные**.

## Настройки расширения (popup)

Модем A:
```
modemMethod:  'at'                    # путь через локальный хелпер
modemHost:    'http://127.0.0.1:8891'
modemSlot:    'A'
modemEnabled: true
```

Модем B: порт `8892`, слот `B`.

`method: 'at'` здесь — «через локальный хелпер»: и AT-хелпер (stick mode), и
HiLink-хелпер говорят один и тот же API (`POST /rotate`).

## Смена IP

1. `dataswitch` off→on — ~30–40 с. **На наших SIM не сменяет IP** (операторы
   держат адрес) — проверено 18.10.2026 на обоих.
2. Эскалация: `reboot` через `/api/device/control` (`<Control>1</Control>`) —
   ~109 с, **меняет IP** (проверено: `89.113.141.75 → 89.113.136.120`).

Хелпер делает это сам: пробует dataswitch, если IP тот же — перезагружает.
Расширению возвращает `{ ok, oldIp, newIp, method }`.

## Схема локов на сервере

Отдельный лок на каждый модем: `ip_rotate:A`, `ip_rotate:B`. Крутит IP модема A —
воркеры на B работают, их лок не касается. **Нужен деплой data-server `d599336`.**

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Модем не виден | хаб без питания / USB 3.0 порт | питание Baseus; переткнуть в USB 2.0 |
| Code 43 на USB | глючный порт хаба | другой порт (USB 2.0) |
| Модем как CD-ROM «HiLink» | режим установщика | `D:\AutoRun.exe`, доустановить драйверы |
| `100003` на settings API | права закрыты | не брутфорсить; LAN IP не менять |
| `125003` на dataswitch | путаница кук двух модемов | у каждого модема свой хелпер/процесс |
| IP не меняется после rotate | оператор держит адрес | хелпер сам эскалирует на reboot |
| Chrome не ходит в сеть | прокси не тот / не поднят | `curl -x http://127.0.0.1:8882 https://api.ipify.org` |
| «Failed to fetch» в воркере | конфликт маршрутов | проверить, что все 4 процесса живы |
